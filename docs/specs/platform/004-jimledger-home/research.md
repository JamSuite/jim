## Local Patterns

**Inspection-skill template — `/jim:conf`, `/jim:file`** (mirror for `/jim:ledger`):
- Layout: `SKILL.md` + `scripts/<cli>.sh`; no `assets/`/`references/`.
- Frontmatter: `name:` matches dir; folded `description:` with when-to-use + when-NOT; `argument-hint:`; single own-skill `allowed-tools: Bash(bash ${CLAUDE_SKILL_DIR}/scripts/<cli>.sh *)`; no `agent:`.
- Body: thin (conf 33 lines, file 72 lines) — purpose line, dispatch, `## Examples`, `## Notes`. Strictly read-only (sole grant is Bash to its own CLI).

**⚠ The passthrough pattern does not transfer directly.** conf/file dispatch the whole CLI via `!`bash …`$ARGUMENTS`` because those CLIs are entirely read-only. jimledger is not — a blanket `$ARGUMENTS` passthrough would let `/jim:ledger commit-map …` reach a mutating verb, violating AC5. `/jim:ledger` needs a **curated read-only dispatch** (its own inspection subcommands → jimledger read verbs), not a blanket passthrough. Mechanism is an architect/plan decision.

**meta-skill checklist** (`skills/meta-skill/SKILL.md`) — the AC6 bar: `name: ledger` matches dir; SKILL.md ≤ 500 lines; own-skill `${CLAUDE_SKILL_DIR}/scripts/jimledger.sh` allowed-tools exactness (no bare `Bash(bash *)`); sentinel + sigil discipline; POSIX-only. A read-only inspector needs neither approval gate nor candidate batch.

**Test convention (resolves Open Question #1):** inspection SKILL.md prompts have **no** bash tests — validated by the meta-skill checklist only. So `/jim:ledger` needs no test file; `tests/jimledger.sh` (the CLI test, testlib.sh conventions + git_fixture helper) simply updates its path constant.

**Move mechanics:** `git mv` preserves history (AC1). The `BASH_SOURCE`-relative resolver is deliberate (ARCHITECTURE.md `:377` Scripting Layer) — it travels across cross-agent install scopes where `${CLAUDE_PLUGIN_ROOT}` does not apply — so the move changes only the relative hop, not the pattern.

## Security & Performance
- No runtime security-surface change: a code move plus a read-only wrapper. The ledger `metrics` channel is script-generated/trusted. The one thing to get right is the read-only boundary — `/jim:ledger` must surface read verbs only and exclude the mutating/commit family (AC5).
- No performance impact; identical CLI behavior (AC4).

## Recommendations

**Alignment.** This work aligns with VISION.md (transparency — a `/jim:ledger` inspection surface symmetric with `/jim:conf`/`/jim:file` makes the institutional-memory ledger legible; the partition's coherence is a stated pillar) and with ARCHITECTURE.md's Plugin Conventions (`:347`) and Scripting Layer (`:377`) — the relocation removes a declared exception (the file-level carve-out) and brings `jimledger.sh` in line with the one-CLI-per-platform-skill shape of `conf`/`file`. No divergence from a locked constraint.

1. **`/jim:ledger` dispatch (architect):** a small curated read-only subcommand set → jimledger read verbs (`metrics`, `last-reconcile`, `reconcile-series`, `updates-since`, plus a stage-event view of `ledger.md`), not a blanket `$ARGUMENTS` passthrough. Note: jimledger has no explicit "list events" read verb, so a stage-event view either reads `ledger.md` directly or the plan adds a small read-only `events` verb (an additive; architect to weigh vs. keeping the CLI untouched per AC4).
2. **Sequence:** `git mv` → fix the 2 resolvers + test constant (unblocks the CLI test) → flip review's own-skill sites to cross-skill → update the 9 other allowed-tools + all cross-skill body call sites → author `skills/ledger/SKILL.md` → update live partition docs (`BLUEPRINT.md` territory + platform blueprint) + `docs/features/ledger.md`. Let `/jim:arch` regenerate `ARCHITECTURE.md` at the build gate.
3. **Blueprint/territory refresh (Open Question #2):** the platform Territory line + carve-out note are hand-declared map content → a `/jim:blueprint` map-tier edit (the reconcile never rewrites hand-declared territory). Recommend a post-build `/jim:blueprint platform` + map update; end state is identical whether folded into build or run after.
