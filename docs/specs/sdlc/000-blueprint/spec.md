# sdlc — blueprint

*The current, present-tense specification of the `sdlc` group: its
responsibilities, exposed and required surface, structure, and load-bearing
invariants. Generated by `/jim:blueprint sdlc`; every claim traces to the
group's specs, ARCHITECTURE.md, and code.*

## Responsibility

The `sdlc` group is jim's phase-gated development lifecycle: scoping
(`/jim:spec` + `/jim:spec-check`), investigation (`/jim:research`), planning
(`/jim:plan`), design-time security (`/jim:sec`), implementation
(`/jim:build`, `/jim:debug`), and post-build review (`/jim:review`) — each
stage producing a durable artifact and halting for human approval. Around the
pipeline it owns the strategic documents (`/jim:vision`, `/jim:roadmap`,
`/jim:arch`, `/jim:brainstorm`), the agent personas that staff every stage,
and the authoring toolchain jim builds itself with (`/jim:meta-skill`,
`/jim:meta-agent`, the meta-matrix probe family) — making it the enforcement
home of the plugin's authoring conventions.

## Provides

- **SDLC command surface** — `/jim:spec`, `spec-check`, `research`, `plan`,
  `sec`, `build`, `debug`, `review`. Guarantee: each produces a durable
  artifact and halts for human approval — no phase auto-advances, nothing
  auto-ships; every stage records `started`/`finished` ledger events, the
  event data downstream metrics and blueprint updates consume.
- **`review.md` + verdict record** — the review's verdict is assigned and
  recorded before the living-intent sensor runs (the sensor can never set
  it), committed path-scoped via `commit-review`; the sensor's VERIFY-OUTCOME
  block is handed to the blueprint update's fork instead of re-running the
  engine, and every un-forked in-change violation is offered as an issue so
  no sensed violation is dropped.
- **Agent personas** — `@jim:pm`, `@jim:architect`, `@jim:researcher`,
  `@jim:coder`, `@jim:security`, `@jim:reviewer`, `@jim:investigator`,
  `@jim:meta`. Guarantee: each is a bounded role that stops after its
  artifact; the investigator is read-only by construction.
- **Authoring/validation authority** — `/jim:meta-skill` and `/jim:meta-agent`
  checklists enforce the plugin-wide authoring conventions (naming,
  allowed-tools exactness, sentinel vocabulary, sigil discipline, budgets) on
  every group's skills and agents; the meta-matrix family probes the runtime
  substitution model those conventions rest on.
- **Strategic doc authorities** — `VISION.md` (`/jim:vision`), `ROADMAP.md`
  (`/jim:roadmap`), `ARCHITECTURE.md` (`/jim:arch` — the sole maintenance
  surface), and `docs/brainstorms/` capture (`/jim:brainstorm`).

## Requires

- `platform.jimconf-cli` / `platform.jimfile-cli` — config, path, id, and
  timestamp resolution from every skill in the group.
- `platform.jimledger-cli` — stage events from every pipeline skill;
  `metrics`/`diff`/`files` and `commit-review` from the review flow.
- `issue.emitter` + `issue.candidate-batch-contract` — the end-of-run § 7a
  candidate batches from the surfacing skills (spec, research, plan, build,
  debug, sec, review, brainstorm).
- `blueprint.advisor` — `/jim:spec` reads the project map on every spec and
  routes mint-new through the map surface.
- `blueprint.blast-radius-facts` — `/jim:plan` reads the contract graph's
  edges (`jimverify.sh edges`) for the provider-group advisory.
- `blueprint.living-intent-sensor` — `/jim:review` invokes the verify engine
  (change-scoped) and dispatches the judge under its own grant; the
  post-review update offer routes to the blueprint write surface.
- `blueprint.gate-presentation-rule` — the meta-skill / meta-agent checklists
  cite the canonical gate-presentation reference.

## Structure

- **Pipeline skills** — `skills/{spec,spec-check,research,plan,build,debug,
  sec,review}/`, each `SKILL.md` plus assets/references (templates, DoD
  checklists, TDD guide).
- **Strategic skills** — `skills/{vision,roadmap,arch,brainstorm}/`.
- **Meta toolchain** — `skills/{meta-skill,meta-agent}/` and the
  `skills/meta-matrix*` probe family.
- **Personas** — `agents/{pm,architect,researcher,coder,security,reviewer,
  investigator,meta,meta-matrix-probe}.md`; the reviewer preloads the review
  and verify skills; meta delegates to pm/architect/researcher via its Agent
  grant.

`skill-budget` names `registry:skill-line-budget` — the operator activates it
by setting `verify_command_skill_line_budget` in `jimconf.toml`; until then the
engine reports it `unconfigured` and runs nothing. The plugin-wide convention
rows bind every group's skills and agents while scoped verification checks only
this group's territory — that enforcement-scope gap is tracked as an open
cross-group contract issue.
